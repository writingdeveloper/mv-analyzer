# Open-source release model

MV Analyzer keeps private research provenance separate from the public source distribution.
The existing canonical repository contains raw collection logs and historical artifacts that are
useful for provenance but unsuitable for direct publication. **Do not change that repository to
PUBLIC without rewriting history.**

## Public release flow

```bash
python scripts/build_public_release.py --out dist/public-release
python scripts/audit_public_release.py dist/public-release
```

The builder creates the source tree intended for a fresh public Git history. It:

- removes internal agent/project-planning files and pilot artifacts;
- omits raw population/enumeration/batch provenance;
- removes legacy self-contained HTML containing embedded thumbnails;
- removes `thumb_text_content` from public CSV/JSONL tables;
- removes local image paths from the public reliability sample;
- preserves aggregate research inputs needed for tests and the static Web explorer;
- writes `PUBLIC_RELEASE_MANIFEST.json` with the canonical source commit and policy version.

The public source tree is licensed under Apache-2.0. `DATA_LICENSE.md` separately describes
project-authored dataset/annotation rights and third-party metadata boundaries.

## Why a clean history?

`python scripts/audit_git_history.py --root .` confirms that the canonical history contains prior
versions of raw OCR fields, local paths, and legacy embedded-media HTML. Deleting those files in
`master` does not remove them from old commits. A fresh public history avoids publishing that
material while preserving the private canonical history for research provenance.

## Release candidate verification

Before creating/updating a public mirror:

1. Build and audit `dist/public-release`.
2. Install only that tree in a fresh Python environment and run the full CPU tests.
3. Generate `web/public/data`, then run Web unit/type/build and Playwright.
4. Initialize a new Git repository from the audited tree and commit it.
5. Clone that new repository into another directory and rerun the public-tree audit/history audit.
6. Only then push to a public GitHub repository.

The canonical private repository remains the source of truth for raw provenance; public releases
are reproducible, sanitized source snapshots.

## Final repository topology

- `writingdeveloper/mv-analyzer-research-private` — PRIVATE raw-provenance/canonical research repository.
- `writingdeveloper/mv-analyzer` — PUBLIC clean-history source repository generated by the release builder.

The public repository must never receive the private canonical `.git` history. Future public releases are generated from the private provenance repo, audited, and then applied to the public source repository as sanitized source commits.
