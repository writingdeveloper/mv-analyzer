# mv-analyzer

**English** | [한국어](README.ko.md)

**MV Analyzer turns a music video into evidence-backed answers to a simple question: _why does this video feel the way it does — and why might I like it?_** It measures visuals, editing, audio, lyrics, synchronization, hooks and packaging **100% locally**, then keeps the numbers as an auditable evidence layer instead of ending with a dashboard.

> **Status**: research cycle 1 complete (Vocaloid, N=50) + K-pop replication (N=50). **Paper draft complete** — English IMRaD + Korean report: [`docs/paper/paper.md`](docs/paper/paper.md) · [`docs/paper/paper.ko.md`](docs/paper/paper.ko.md). The raw-provenance research repository remains **private**; the public `writingdeveloper/mv-analyzer` repository is published from an audited **clean-history** source tree generated by `scripts/build_public_release.py`. See [`docs/open-source-readiness.md`](docs/open-source-readiness.md) and [`docs/open-source-release.md`](docs/open-source-release.md).


## Reason Engine — “So why?” before the charts

Analyze report v2 is now the evidence layer for a deterministic **Reason Engine**. The Claim Engine decides which statements are supported, contradicted, or still insufficient **before** language rendering. An LLM is not required to explain a result and is never allowed to invent a reason that is absent from structured evidence.

Three questions stay separate:

- **What makes this MV distinctive?** — reference-corpus comparison.
- **Why does this MV feel like this?** — measured multi-feature composition such as framing, pacing, audio density or opening structure.
- **Why might I like this MV?** — optional comparison with an explicit local favorites profile; high-variance hypotheses are reported as **not supported**, not silently turned into a preference.

Existing local analysis, no GPU or network:

```bash
mva reason-export data/VIDEO_ID --out reason.json --benchmark-domain vocaloid
```

Attach a personal favorite list:

```bash
mva reason-export data/VIDEO_ID --out reason.json --favorites work/favorites_queue.txt --data data
```

New URL through the existing local analyzer, followed by Reason Engine:

```bash
mva explain "https://www.youtube.com/watch?v=..." --lang ko --benchmark-domain vocaloid --out reason.json
```

The public Analyze page accepts both Analyze report JSON and portable Reason JSON. For an imported report it derives the same versioned reference/feel claims in the browser, then shows **So why?** before PCA and raw feature details.

### Analyze My MV — local-first report workflow

Heavy analysis stays on your machine. Generate a portable, public-safe report locally, then open the deployed **Analyze** view and import the JSON file. The public Web app reads the file only in the current browser tab; it does not upload the report.

```bash
pip install -e .
mva analyze "https://www.youtube.com/watch?v=..." --web-report my-mv.json
```

Viewer: **https://mv-analyzer.writingdeveloper.blog/#/analyze** · English: **https://mv-analyzer.writingdeveloper.blog/?lang=en#/analyze**

The result is benchmarked against **Extreme Reference Corpus v2026.07**, an extreme-group research sample. Percentiles are therefore **reference-corpus percentiles**, not market percentiles or success probabilities. Reports intentionally exclude raw media, raw lyric/OCR text, local paths, cookies/headers, and signed media URLs.

Maintainer deployment (requires a clean worktree and records the exact HEAD in the public manifest):

## Research question

> Among Vocaloid MVs published on original producer channels (2025-04 to 2026-04), how do the top-25 and bottom-25 extremes by views-per-subscriber differ in audio, lyrics, visuals, and packaging?

## Key findings (cycle 1)

Full report: [`docs/reports/2026-07-16-p5-report.md`](docs/reports/2026-07-16-p5-report.md) · Interactive dashboard: `docs/reports/dashboard.html`

| Signal | Top group | Bottom group | Cliff's δ |
|---|---|---|---|
| Cuts per minute | 23.9 | 5.5 | +0.72 |
| Median shot length | 1.5 s | 6.2 s | −0.79 |
| Cuts in first 15 s | 5 | 2 | +0.57 |
| Characters per scene | 1.24 | 0.95 | +0.46 |
| Thumbnail has text | 9/25 | 24/25 | p < 0.0001 |
| Premiere release | 13/25 | 4/25 | p = 0.016 |

Things that **don't** separate the groups (genre conventions, not popularity factors): lyric themes (farewell), negative sentiment, first-person voice, song length, loudness, upload day/time.

**Read the caveats**: these are correlations from an extreme-group design, not causes. Fast cutting and character art density are plausibly proxies for production investment. A channel-prolificacy confounder (δ −0.75) is documented and scheduled for controlled reanalysis. **[Updated 2026-07-21]** The premiere-release row keeps the original cycle-1 result, but a within-channel matched reanalysis found the effect vanishes (55 pairs, Wilcoxon p=0.46, median ratio 1.07×) — the original result (13/25 vs 4/25) now looks like channel-level confounding. See [`docs/reports/2026-07-21-premiere-matching.md`](docs/reports/2026-07-21-premiere-matching.md).

## Pipeline (all local, no external APIs)

| Stage | Tool |
|---|---|
| Collection & metadata | yt-dlp + ffmpeg (with deno JS runtime) |
| Scene boundaries / cut rhythm / color | PySceneDetect 0.7 (ContentDetector t=15) + OpenCV |
| Audio (BPM, key, LUFS, energy curve, beats) | librosa 0.11 + ffmpeg ebur128 |
| Scene semantic tagging | Ollama `qwen2.5vl:7b`, temperature 0, closed vocab |
| Lyrics — hard-sub OCR | same VLM, bottom-30% crop @0.5 fps |
| Lyrics — ASR fallback | demucs (vocal separation) + faster-whisper large-v3 |
| Lyrics topic/sentiment tagging | Ollama text call, closed vocab |

GPU stages never run concurrently (16 GB VRAM): ASR runs in a separate process, and the VLM model is explicitly unloaded beforehand.

## Usage

The recommended entry point for exploration is the Web Research Explorer above. The installable `mva` CLI remains the analysis, QA, and snapshot-generation engine; existing root scripts such as `python analyze.py ...` remain compatible.

```bash
# CPU/base tooling; GPU ASR/VLM remains an optional environment concern
pip install -e .

# Environment and data QA — no model inference or CUDA work
mva doctor
mva config                         # show measurement models/thresholds
mva status
mva qa --tests
mva stats-qa --table work/features_table.jsonl

# Read-only local index + feature-space exploration
mva index
mva index --check                  # verify source-fingerprint freshness
mva search <query> --limit 50        # DuckDB search across title/lyrics/scene tags
mva similar <video_id> --limit 10
mva benchmark <video_id>
mva outliers --limit 10
mva motion <video.mp4|video_id>       # experimental CPU optical-flow metrics
mva motion-scenes <video_id>          # per-scene motion class (static image / animated still / motion clip)
mva motion-scenes-batch               # whole corpus → data/<id>/motion_scenes.json + work/experiments/motion/
mva caption-scan                      # YouTube caption-track availability scan (network only, no lyric text)
mva motion-label                      # blind stratified sample + strips for the motion-class human-label gate
mva motion-label-score                # score a filled label sheet against the key (agreement + Cohen's kappa)
mva evaluate-vlm --baseline           # rescore current VLM against blind labels
mva evaluate-vlm candidate.json       # score candidate-model output, CPU only

# Analyze / diagnose
mva analyze <YouTube URL> --lang ja|ko
mva analyze <YouTube URL> --web-report my-mv.json --benchmark-domain all|vocaloid|kpop
mva diagnose <YouTube URL>

# Evidence layer over analyzed videos
mva talk list
mva talk show <id>
mva talk timeline <id>
mva talk at <id> <seconds>
mva talk search <query>
mva talk compare <id> <id> ...
mva talk profile --list work/favorites.txt   # shared traits of a taste list vs. corpus percentiles + palette (distinctive / shared / convention / irrelevant)
mva talk export <id>                         # OpenMontage-compatible analysis JSON → work/exports/ (input for openmontage-reference-lab --from-analysis)
mva talk sanitize <vision.json> --typography abstract   # strip reference-only artifacts (subtitle band, pillarbox, on-screen text) for generation use
mva gen-frames <id> --clean-source <clean id>           # generation-use reference frames (re-cut from a subtitle-free version, pillarbox removed)
mva talk export <id> --keyframes <dir>                  # export against that frame set (the I2VA first frame)

# Sampling / batch / reports
mva collect discover --queries work/queries.txt --out work/channels_candidates.csv
mva batch
mva report
mva dashboard
mva trend --report
```

New analysis runs write `analysis_manifest.json` with the git commit, pipeline schema and per-stage fingerprints. Legacy artifacts are never invalidated automatically. With `--refresh-stale`, only artifacts that already have provenance and whose code fingerprint changed are regenerated. Corrupt JSON caches are repaired on the next analysis run.

The unified `mva` CLI forces UTF-8 for child Python processes on Windows. Direct root-script usage should still set `PYTHONUTF8=1`. CPU QA/index/search/similarity commands do not use the GPU. GPU-producing analysis stages keep the sequential Ollama VLM/demucs/faster-whisper policy and now use a busy guard: by default analysis aborts before touching GPU stages when another workload is already using 2GB+ VRAM or 35%+ utilization; `--force-gpu-busy` is the explicit override. DuckDB remains a local cache rather than a source of truth; `mva search` automatically rebuilds it when the JSON/code source fingerprint changes. Because the local index can contain lyric lines, the `.duckdb` and sidecar are gitignored and must not be committed or distributed.

## Research process (completed cycle)

1. **P1 — Sample design**: population, normalization (views/subscribers), extreme groups, exclusion rules → [spec](docs/superpowers/specs/2026-07-15-p1-sample-design-design.md)
2. **P2 — Pipeline**: single-CLI analyzer + collector, two validation gates against a hand-verified pilot
3. **P3 — ASR**: bottom-crop OCR failed on 2/2 original-channel videos (full-screen typography / English subs) → demucs+whisper adopted, re-validated
4. **P4 — Batch**: 50/50 videos analyzed (resumable batch driver; Ollama/VRAM sequencing; YouTube bot-flag mitigation)
5. **P5 — Statistics**: Mann-Whitney U + Cliff's δ + BH-FDR; effect-size ranking; confounder checks

- [x] **Measurement accuracy validation** (2026-07-17): VLM tags vs. independent blind annotator — 9/10 significant findings rest on deterministic instruments; character-count passes (ρ 0.80); mood/shot_type downweighted ([report](docs/reports/2026-07-17-measurement-reliability.md))
- [x] Copyrighted lyrics purged from git history + CI (GitHub Actions)
- [ ] Larger samples (40+ per group → detects medium effects)
- [x] **Cross-domain replication** (2026-07-21): K-pop 50/50 complete — domain comparison report vs. vocaloid (`docs/reports/2026-07-21-domain-comparison.md`)
- [x] **3 new analyses** (2026-07-21): within-channel premiere matching, lyrics-structure, heatmap retention (`docs/reports/2026-07-21-heatmap-retention.md`) — pre-registered gate **FAIL** (criteria: q<0.05 & |δ|≥0.33, or matched p<0.05 — nothing qualified → back to planning, `docs/reports/2026-07-21-new-analyses-gate.md`)
- [x] **Measurement fix: ASR lyric-language filter bug** (2026-07-21): `asr_to_lines` was misclassifying sung English lines as hallucination, discarding them en masse for K-pop → fixed (Latin chars now count + consecutive-duplicate collapse) → K-pop valid sample recovered 28→47/50 (vocaloid unchanged at 47/50). Gate re-run: still **FAIL** (same criteria, nothing qualified) — details: `docs/reports/2026-07-21-lyrics-structure.md`
- [x] **Mid-tier sample / monotonicity** (2026-07-22): added a Vocaloid 40–60th-percentile mid-tier group (bottom-25/middle-25/top-25) — all **6/6** pre-registered editing-rhythm metrics show monotonic dose-response gradients (Kendall τ, all q<0.005; e.g. cuts/min 5.5→17.5→23.9) ([report](docs/reports/2026-07-22-monotonicity.md))
- [x] **Color/visual-dynamics derived features**: brightness/saturation variability, mean/P90 color change and unique-color ratio derived from existing scene artifacts without GPU/media reprocessing
- [x] **CPU optical-flow motion instrument**: opt-in mean/median/P90/static-ratio metrics; intentionally not mixed into the existing 128-video corpus without a new validation gate
- [x] **Formal feature policy/input QA**: centralized the P5 allowlist; `ext_*`/`motion_*` experiments cannot silently enter the existing hypothesis tests; the current 50-row table passes 25/25 group and coverage QA
- [x] **DuckDB freshness tracking**: data/derived-code fingerprint sidecar with automatic stale rebuild before search
- [x] **CI research guardrails**: every branch push runs Python 3.12/3.13 pytest, Ruff F-only correctness checks, P5 input-table QA and public CSV dataset invariant QA
- [ ] Formal music-structure-model chorus position (e.g. all-in-one-infer); a repeated-lyric `ext_lyrics_first_chorus_*` proxy is available now
- [x] **Per-scene motion classes** (2026-09-02): Farneback flow mean/variance splits scenes into static image / panned still / real motion (`motion_scene_*`, experimental prefix)
- [x] **Motion-class human-label gate (2026-09-03): FAILED** — blind 45-item comparison, agreement 0.556 / κ 0.333 (gate 0.75 / 0.60). No threshold or model reaches it: the ceiling tuned on the labelled sample itself is 0.667 (3-class) and 0.733 (binary). `motion_clip` precision is 1.000 (recall 0.484), so it survives only as a **one-sided** indicator. `motion_scene_*` stays out of hypothesis testing; the static-ratio row of the exploratory group comparison is withdrawn ([report](docs/reports/2026-09-03-motion-gate.md))
- [x] **Caption-track availability scan** (2026-09-02): of 128 videos, 76 have manual caption tracks and 50 have one in the song's language (ja 14/77 · ko 36/51). 7 of the 12 lyric-less videos and 32 of the 58 ASR videos could be served from captions — adopting a `cc` lyric source is a measurement change and falls under the full-corpus re-run rule
- [x] **Generation-use prompt variant** (2026-09-03): `talk sanitize` strips subtitle bands, pillarbox bars and on-screen lyrics clause by clause (82 clauses across 49 shots) and rewrites text-dependent phrasing into shape phrasing; the reference-lab rerun drops artifact mentions 96 → 0 with 49/49 H3-ready
- [x] **Generation-use reference frames** (2026-09-03): I2VA conditions on the image, so cleaning the prose is not enough — 29 of the 49 keyframes still carried pillarbox bars and burned-in fansubs. `gen-frames` re-cuts the same timestamps from a subtitle-free version and crops the bars, keeping the MV's own typography
- [x] **Taste profile / production bridge** (2026-09-02): `talk profile` places a list's shared traits on corpus percentiles (distinctive / shared / convention / irrelevant) with palette deltas; `talk export` writes OpenMontage-compatible JSON that `openmontage-reference-lab --from-analysis` carries through to H3 prompt generation (no code dependency, AGPL boundary kept)
